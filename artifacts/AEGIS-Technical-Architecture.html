Status note (October 2026). This is the original architecture design. Some parts describe the original concept, not the software as built. Where they differ, this box is correct:
  • Built and running: AEGIS coordinator + 4 specialist agents (PULSE heart rate/SpO₂, GENE IL-6, MIRROR sleep, SOLARIS radiation), rule-based detection, trend forecasts, cascade detection, PREVENT/PROTECT protocols, DeepSeek explanations with an automatic fact check, phone alert to the on-call flight surgeon.
  • Data: vitals are simulated (no wearable hardware). IL-6 is modelled from stress and radiation, not measured. Radiation is judged against the Mars-transit background measured by Curiosity RAD (1.84 mSv/day). Real NASA data (Inspiration4 / OSDR OSD-575, NTRS abstracts) is used to check the rules and as the RAG knowledge base; nothing is “trained” on it.
  • Prediction scope: in the demo AEGIS forecasts a cascade about 2–3 minutes before the third domain crosses its limit (the demo runs a compressed 6-minute build-up). On a mission the same trend method would work on hours-to-days data; that has not been validated.
  • Not built (concept only): HRV, CRP, cognitive tests (PVT/n-back), live DSCOVR/GOES feeds, RadLab dose model, z-score/EWMA baselines, genomic (TP53) analysis, a 30-second auto-execute override. PROTECT protocols are raised for a human to confirm.
  • Category strategy now: Best Mission Concept (primary), Best Use of Technology (secondary).
Current numbers and test results: README.md and AEGIS-Accuracy-Report.html.

1 System Overview

AEGIS is a three-tier autonomous health system designed for zero-Earth-dependence missions. Tier 1 (Predict) uses multi-agent trend forecasts to flag an emerging health cascade before it forms (about 2–3 minutes ahead in the compressed demo; hours to days on a mission, not yet validated). Tier 2 (Prevent) delivers proactive intervention recommendations to stop problems before they escalate. Tier 3 (Protect) raises emergency protocols at once when prevention fails, for a human to confirm, and phones the on-call flight surgeon — no Earth delay, no waiting for Mission Control.

Knowledge-Grounded: All decisions are backed by RAG-powered access to NASA HRP protocols, OSDR research datasets, and real-time space weather feeds — ensuring evidence-based responses, not guesswork.

4 Tier 2: PREVENT — Proactive Intervention

Once a cascade is detected, AEGIS recommends specific interventions to stop the problem before it escalates to an emergency.

Sleep Optimization
Adjust circadian lighting schedule, recommend melatonin timing, reduce pre-sleep screen exposure
EVA Scheduling
Delay non-critical EVAs during elevated radiation periods, reduce exposure duration
Pharmacological
Recommend rest, reduced exertion and closer monitoring (approved countermeasure steps only)
Workload Adjustment
Reduce mission task load, increase rest periods, redistribute duties among crew

5 Tier 3: PROTECT — Emergency Response Flow

When predictive detection (Tier 1) and preventive intervention (Tier 2) have failed or weren't possible, Tier 3 activates immediate autonomous response.

1
🚨 Emergency Detected
Biometric sensors detect abnormal readings (high heart rate, low SpO2, elevated temperature) or spacecraft sensors detect hazardous conditions (radiation spike, pressure drop).
event: { type: "biometric_alert", crew: "chen", metric: "heart_rate", value: 145 }
2
📢 AEGIS Alerts Crew
AEGIS immediately announces the emergency via voice interface and visual alerts. Crew members are informed of the situation and given the option to respond.
AEGIS.speak("Commander Chen, elevated heart rate detected. Do you need assistance?")
3
⏱️ Immediate alert, human confirms
AEGIS waits exactly 10 seconds for any human response. This gives crew members time to acknowledge the alert, provide context, or take manual control of the situation.
await waitForResponse({ timeout: 10000, listenFor: ["voice", "button", "gesture"] })
4
🔀 Decision Point
If response received: Human takes control. AEGIS provides support as requested.
If no response: AEGIS assumes crew is incapacitated and initiates autonomous response.
5
⚡ MCP Server Triggered
AEGIS calls the MCP server to run simulations and determine the optimal emergency protocol based on current crew positions, health status, and environmental conditions.
mcp.run_simulation({ scenario: "high_heart_rate", affected: "chen", crew_state: {...} })
6
🚀 Protocol Executed
The MCP server returns the recommended protocol. AEGIS executes it automatically: moving crew to safe positions, sealing modules, adjusting life support.
mcp.execute_protocol({ name: "stress_response", steps: ["dim_lights", "play_calm_audio", "move_to_quarters"] })
7
📱 Earth Mission Control Notified via Slack
AEGIS sends an alert to Earth Mission Control via Slack, including incident details, crew status, actions taken, and request for guidance if needed. This creates an audit trail and allows ground support to monitor the situation.
slack.alert_mission_control({ severity: "high", incident: "elevated_hr", crew: "chen", protocol: "SIGMA-1", status: "executing" })
mcp.execute_protocol({ name: "stress_response", steps: ["dim_lights", "play_calm_audio", "move_to_quarters"] })

6 System Components

🤖
AEGIS AI Agent
The central intelligence that monitors all inputs, makes decisions, and coordinates responses. Built on LLM technology with real-time sensor integration.
Python + LLM + Real-time Processing
⚡
AEGIS Protocol Server
Exposes simulation and protocol execution tools via the Model Context Protocol. Handles the logic of running emergency scenarios and commanding spacecraft systems.
FastMCP + Python + JSON-RPC
💬
Slack MCP Server
Sends alerts and status reports to Earth Mission Control via Slack. Enables real-time notification of incidents, protocol executions, and requests for guidance.
@modelcontextprotocol/server-slack
💾
Data MCP Server
Persistent storage for incident logs, crew health history, and protocol outcomes. Enables trend analysis and post-incident review.
SQLite + mcp-server-sqlite
🧠
Knowledge RAG Server
Semantic search over NASA HRP research, mission protocols, and OSDR datasets. Agents retrieve evidence-based medical protocols and research findings in real-time.
ChromaDB + SentenceTransformers + FastMCP
🖥️
Mission Control Dashboard
Real-time visualization of crew status, spacecraft state, and emergency protocols. Includes 2D simulation view of astronaut movements.
HTML/CSS/JS + WebSocket
🗣️
Voice Interface
Bidirectional voice communication with crew. AEGIS speaks alerts and instructions; crew can respond verbally to acknowledge or override.
Web Speech API + TTS + STT
📊
Sensor Integration Layer
Aggregates data from biometric wearables, spacecraft environmental sensors, and location tracking systems into a unified data stream.
MQTT + Sensor APIs + Data Fusion
🔐
Safety Override System
Hardware-level controls that allow crew or Mission Control to override any autonomous action. Human authority is always preserved.
Hardware Interlocks + Auth Layer

Tool Name Description Parameters

get_crew_status Retrieve current location, health metrics, and status for all crew members crew_id (optional)
get_ship_status Retrieve current spacecraft environmental readings and system states module (optional)
move_crew Direct a crew member to relocate to a specific module crew_id, destination_module
seal_module Seal or unseal a spacecraft module for isolation protocols module_id, seal_state
adjust_environment Modify lighting, temperature, or life support in a module module_id, settings
broadcast_alert Send voice or visual alert to specific crew or entire spacecraft message, target, severity

9 Emergency Protocols

💓
Stress Response
Activated for elevated heart rate or stress indicators. Dims lights, plays calming audio, guides crew member to rest quarters.
☢️
Radiation Shelter
Activated for radiation spikes. Immediately moves all crew to the shielded shelter module and seals non-essential areas.
😴
Sleep Adjustment
Activated for fatigue or circadian disruption. Enforces rest period, adjusts lighting schedule, reduces workload assignments.
🏥
Medical Emergency
Activated for medical alerts. Moves patient to medbay, dispatches trained crew member, prepares medical equipment, alerts Earth.
🚶
EVA Halt
Activated during spacewalk emergencies. Immediately recalls EVA crew, prepares airlock, and stands by medical support.
🚨
General Emergency
Activated for unclassified emergencies. All crew to command module, full system check, direct communication with Mission Control.
