01 The Problem

A crew en route to Mars has no flight surgeon, no emergency evacuation, and a 24-minute communication delay. Space radiation is silently rewriting their DNA. Microgravity is deconditioning their cardiovascular system. Isolation is degrading their cognition. And the only person who can catch these changes early enough to act — is the astronaut themselves, with no medical training and a mission to run.
Predict problems days early. Prevent them with timely intervention.
Protect the crew when prevention fails.
Three tiers. Earth-independent decision-making.

The core medical challenge of deep-space flight is not data collection — it is interpretation without experts. An astronaut can measure their heart rate variability. They cannot know whether a 14% drop over 8 days, combined with a subtle shift in their inflammatory cytokine panel and a recent solar particle event, is the early signature of an immune cascade that will peak in 5 days. AEGIS can.

02 The Solution

AEGIS is not a dashboard. It is a crew member — a team of five specialized AI agents operating across a three-tier autonomous health system designed for zero-Earth-dependence missions.

🔮
Tier 1
PREDICT
Multi-agent cascade detection forecasts a cascade before it forms: about 2–3 minutes ahead in the compressed demo; on a mission the same trend method would run on hours-to-days data (not yet validated). Combines heart, inflammation (modelled), sleep and radiation signals.
→ Day 47: subtle pattern detected
🛡️
Tier 2
PREVENT
Proactive intervention recommendations — adjusted sleep schedules, modified EVA plans, pharmacological countermeasures — delivered hours to days before a cascade reaches crisis.
→ Day 51: "reduce EVA exposure, adjust sleep"
⚡
Tier 3
PROTECT
When prevention fails, autonomous emergency protocols alert the crew and the on-call flight surgeon immediately (dashboard alarm + phone call). No Earth delay. A human confirms the protocol; auto-execution is a future option, not built.
→ T+0: crew alerted · flight surgeon phoned · human confirms

The system is built on three scientific pillars:

Pillar 1 — Genomics
Personal biomarker baselines using NASA's Inspiration4 and OSDR data. AEGIS tracks individual response profiles to radiation and microgravity stressors, with reference ranges drawn from real spaceflight omics research.
Pillar 2 — Multi-Agent Intelligence
Five specialized agents translate raw biomarker data into plain-English crew guidance using rule-based detection and personal statistical baselines. The orchestrator synthesizes all five streams into a unified health narrative the astronaut can act on. LLM enhancement is a configuration option, not a dependency.
Pillar 3 — Space Context
Real-time space weather data, radiation dose accumulation, and mission context are first-class inputs — not afterthoughts. AEGIS understands the difference between an abnormal reading on Earth and the same reading on day 90 of a Mars transit.

03 The Agent Crew

🧬
GENE
Genomic Drift Analyst
"I read your DNA so you don't have to."

GENE is the scientific core of the system. Reference ranges and response profiles are drawn from NASA's Inspiration4 multi-omic dataset — the only publicly available multi-layered genomic data from real civilian astronauts — it tracks how the astronaut's biomarkers drift from their personal pre-mission baseline across key dimensions: inflammatory markers (IL-6, CRP from blood panels), immune response indicators, and radiation exposure correlations from the RAG knowledge base.

🔬 Key Innovation

GENE detects multi-stressor response patterns — biomarker changes that emerge when radiation AND microgravity stress combine. Reference profiles are drawn from Inspiration4 and OSDR spaceflight omics research, applied to individual crew baselines for personalized monitoring.

A RAG (Retrieval-Augmented Generation) knowledge base of NASA research papers allows GENE to contextualize its findings against published spaceflight medicine literature in real time.

"Your inflammatory markers are elevated — IL-6 is 2.3× above your pre-flight baseline and CRP is trending up. This pattern is consistent with the immune stress response we'd expect after cumulative radiation exposure, correlating with the M-class solar flare SOLARIS flagged on Day 47. Within expected range for now, but the trajectory is worth watching. Flagging to AEGIS for trend monitoring."
NASA OSDR API Inspiration4 Dataset ChromaDB RAG Anomaly Scoring Model MiniLM Embeddings
💓
PULSE
Physiological Time-Series Monitor
"I watch the numbers you forget to check."

PULSE runs continuous anomaly detection using statistical baselines (z-score, EWMA) on rolling physiological time-series: heart rate variability, sleep stage quality, resting heart rate, blood pressure trend, SpO2, and activity patterns. It works on simulated mission data modeled on published ISS physiological studies — or can ingest real wearable data when available.

📈 Key Innovation

PULSE compares the astronaut to themselves, not population norms. And it tracks trajectory, not snapshots. A heart rate of 68 bpm is meaningless. A heart rate that has trended from 58 → 68 over 12 days while sleep quality degrades simultaneously is a signal — and that distinction is what separates predictive medicine from reactive monitoring.

When the statistical model flags an anomaly, PULSE contextualizes it against mission history and known spaceflight physiology patterns from the RAG knowledge base — producing a crew-readable finding instead of a raw statistical deviation alert.

"Cardiovascular: 🟡 Watch. HRV has dropped 18% over 6 days — a pattern that in the Inspiration4 cohort correlated with onset of stress-related immune suppression. Sleep quality declining for 4 consecutive nights. Recommend reviewing exercise load and confirming CO₂ scrubber efficiency."
Z-Score Baseline EWMA Trending Time-Series DB Personal Baseline Model ISS Physiology Reference Data
☀️
SOLARIS
Space Weather & Radiation Liaison
"I watch the sun so the crew doesn't get surprised."

SOLARIS ingests real-time DSCOVR solar wind data and GOES satellite solar particle event feeds. It maintains a running cumulative radiation dose estimate per crew member based on mission profile, shielding parameters, and detected SPE events. It forecasts EVA risk windows 24–48 hours ahead using historical solar event data.

🔗 Key Innovation

SOLARIS feeds dose events directly to GENE as causal context. When GENE detects an inflammatory response (elevated IL-6, CRP), SOLARIS can confirm or deny whether a recent solar particle event explains it — creating a validated causal chain from environmental radiation to biological response. This cross-agent causal linking strengthens the system's explainability.

Translates raw space weather telemetry (proton flux, Kp index, Bz component) into crew-actionable, plain-English guidance — not numbers the astronaut has to interpret.

"⚠️ Moderate SPE in progress. Projected additional dose for tomorrow's 4-hour EVA: 8 mSv. Cumulative mission dose post-EVA: 142 mSv (24% of career limit). EVA is GO but I've already alerted GENE to watch your biomarkers for radiation response signatures over the next 72 hours."
DSCOVR API (live) GOES Satellite Feed RadLab (OSDR) Dose Accumulation Model Threshold Alerting
🧠
MIRROR
Behavioral & Cognitive Health Monitor
"I notice what you haven't noticed yet."

MIRROR addresses what NASA HRP identifies as the #1 long-duration mission risk: psychological health. No recent Space Apps team has tackled this domain — which means it's our white space. MIRROR does it through two mechanisms, both consent-driven and non-invasive.

🧠 Key Innovation

Daily 90-second cognitive check-in using clinically validated instruments (Psychomotor Vigilance Test for reaction time, short n-back task for working memory — the same tools used on ISS). MIRROR tracks the astronaut's cognitive performance curve across the entire mission and detects degradation before it becomes impairment. Optional: aggregate linguistic drift analysis on crew journal entries — not mood surveillance, but early warning pattern detection validated in analogue studies.

MIRROR never labels the astronaut. It identifies patterns and offers context. The framing is always: "here's what the data shows, here's what it has historically preceded, here's what you can do about it."

"Cognitive performance is 14% below your personal 30-day average. This pattern in long-duration analogue studies typically precedes motivational decline by 2–3 weeks. Sleep fragmentation is the likely driver based on PULSE data. Recommended: confirm rest day Thursday, review habitat lighting schedule for circadian realignment."
PVT (Reaction Time) n-Back Memory Test Trend Scoring HRP Behavioural Data Personal Baseline
🛡️
AEGIS
Chief Medical Officer & Orchestrator
"The flight surgeon that never sleeps."

AEGIS is the agent the crew talks to. It orchestrates GENE, PULSE, SOLARIS, and MIRROR — calling each for their latest structured summaries, synthesizing them, and handling any crew question in natural language. It is the only endpoint the frontend communicates with directly.

⚡ Key Innovation — The Cascade Alarm

AEGIS implements a convergence detector: when three or more agents reach amber status within a 7-day window, it fires a qualitatively different escalation — a Cascade Alert. Because a signal that appears independently across genomic, physiological, environmental, and behavioral streams simultaneously is not noise. It is a pattern that warrants action. AEGIS applies multi-domain convergence detection, the principle behind clinical early-warning scores, to spaceflight stressors.

AEGIS also maintains the Mission Memory — a full timeline of every health event, agent finding, recommendation, and crew response across the entire mission. The crew can ask "What happened to my health during weeks 6–8?" and receive a narrative answer, not a data dump.

"Four independent health systems are reporting a converging pattern. SOLARIS detected an SPE on Day 47. GENE flagged elevated inflammatory markers (IL-6, CRP) on Day 49. PULSE detected HRV decline and sleep fragmentation on Day 51. MIRROR noted 14% cognitive slowing on Day 53. Together, these match the early profile of radiation-induced immune stress cascade. Initiating countermeasure protocol RECOVER-3: increased hydration, reduced physical exertion for 72 hours, antioxidant supplement schedule."

07 From Prototype to Spacecraft Hardware

A judge will ask: "This uses OpenAI and cloud services — how does that work on a Mars mission with no internet?" The answer is that AEGIS is explicitly architected for deployment autonomy. The prototype uses cloud services for rapid development. The production path replaces them entirely with on-board systems — and the abstraction layer makes that swap a configuration change, not a redesign.

The cloud is the development environment.
The spacecraft is the deployment target.

The Real Constraint — Backed by NASA Research

A Mars-bound spacecraft cannot call the OpenAI API. NASA's own published data confirms one-way communication delays to Mars range from 3 to 22 minutes, peaking near solar conjunction when the Sun can interrupt communications entirely — making any round-trip query take up to 44 minutes. [1] NASA's Software Engineering Handbook explicitly states that "autonomous operation of system and subsystem functions that prevent catastrophic events is essential for ensuring mission success and crew survival." [2]

NASA's published Earth-Independent Medical Operations (EIMO) Concept of Operations — a real active program — states that crew health management for deep-space missions requires "a comprehensive, multi-functional on-board clinical decision support system" because "communication time with ground-based personnel is delayed or non-existent during significant portions of the mission." [3] AEGIS is a prototype of exactly that system.

The Hardware: NASA's HPSC — Built for Exactly This

NASA's High Performance Spaceflight Computing (HPSC) program is developing a next-generation system-on-chip that delivers over 100× the computing capability of current space processors — specifically designed for AI workloads at the edge of space. NASA's own documentation states: "HPSC was designed for autonomy and AI at the edge of space and the demanding fault-tolerance needs of Human Exploration and Operations (HEO) missions." [4] A 2026 NASA paper on autonomous lunar habitats explicitly cites HPSC as the compute substrate for AI-driven autonomous systems. [5]

For context: most current spacecraft run on the RAD750 — a radiation-hardened processor roughly equivalent to a late-1990s desktop. HPSC delivers 100× more performance per watt, placing it firmly in the territory capable of running quantized LLM inference.

Why Quantized LLMs Are Feasible On-Board

A Llama 3.1 8B model quantized to Q4_K_M format requires approximately 3.8–5 GB of RAM and runs at usable inference speeds even on CPU-only hardware. Verified benchmark data from llama.cpp (the open-source inference engine Ollama is built on) shows Q4_K_M at the quality-per-byte sweet spot — "roughly 3.80 GB with a perplexity increase of only +0.0535" versus the full-precision model. [6] Independent benchmarks report 40–150 tokens/second on modern hardware at this quantization level. [7] For medical consultation use — where a response in 5–15 seconds is perfectly acceptable — this is more than sufficient.

Why the Code Swap Is Trivial

AEGIS is designed for LLM provider portability. The architecture supports swapping between providers (e.g. OpenAI, DeepSeek, Ollama) via environment configuration — when LLM enhancement is enabled. The prototype runs fully offline with rule-based agents; LLM integration is a configuration option, not a dependency. ChromaDB already runs in-process as a local file store with no server or network requirement. The entire AEGIS stack containerises via Docker and deploys on any Linux compute node, including HPSC.

On-Board Deployment Model

Pre-departure (Earth):
  → Embed all NASA/HRP research into vector store (ChromaDB local file)
  → Quantize Llama 3.1 8B to Q4_K_M (~3.8 GB, CPU-runnable)
  → Fine-tune on spaceflight medicine domain data
  → Package AEGIS stack into Docker image
  → Load onto spacecraft HPSC compute node

In-flight (zero network dependency):
  → All LLM inference runs locally via Ollama on HPSC
  → Vector search runs in-process via ChromaDB (local SSD)
  → SOLARIS reads on-board radiation dosimeters directly
  → Knowledge base updates downlinked during Earth comms windows
  → Applied incrementally — never blocking active health monitoring
